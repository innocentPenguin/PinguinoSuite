# Site pop-out (055): findings and proposed design

Status: APPROVED by Ivan, IMPLEMENTED, type-checked with cargo check (scratch target dir), NOT built or launched. Needs a real run on Windows (icon, taskbar button, sign-in persistence).

## Goal
Pop innocentpenguin.com out of the Suite into its own window that (1) has its own icon, different from the favicon and the Suite icon, and its own taskbar entry and title, and (2) keeps the site/Twitch login across launches without ever printing or storing credentials ourselves.

## Findings (how the shell works today)
- Tauri 2.12 shell, `App/src-tauri/src/windows.rs`. Pop-outs go through one command `open_window(OpenReq)`, called from the UI as `window.PGWin.open(...)` (`App/src/bootstrap.js`) or by `postMessage` from module iframes. Contract: `Docs/MODULE_CONTRACT.md` "Pop-out windows".
- Every pop-out is a `WebviewWindowBuilder` with label `pop-<name>`, geometry/monitor/always-on-top saved in `<data dir>/windows.json`, reopened at launch by `windows::restore`. The capability file already covers `pop-*`.
- `build_url` accepts ONLY `127.0.0.1` / `localhost` URLs (or shell paths). A remote site URL is refused by design. The main window CSP also has `frame-src http://127.0.0.1:*` only, so the site cannot be iframed in the shell either.
- All windows share one process, one WebView2 profile, the default window icon (`icons/icon.ico`, set in `tauri.conf.json`) and the app identifier `gg.pinguino.suite`. The tray uses the default icon too. No existing pop-out (Link, Multi, Spotify, Voice) sets its own icon, data directory or AppUserModelID; they are all local module pages. So nothing existing covers a remote, logged-in, separately-iconed window; that part is new.
- Tauri 2.12 does provide what we need: `WebviewWindowBuilder::icon()`, `.data_directory()`, `.on_navigation()`, `.on_new_window()`, `WebviewWindow::set_icon()`.

## Proposed design (follows the existing pattern, adds one narrow command)
1. **Same registry, new command.** Add `open_site_window` in `windows.rs` next to `open_window`, reusing `Layouts`, `place`, `snapshot`, `restore` (label `pop-site`, geometry/monitor/on-top remembered, close X = stays closed next launch). `PGWin.openSite()` in `bootstrap.js` plus a "Pop out site" button in the top bar / Settings > Pop-out windows. No parallel window system.
2. **Fixed URL, not a free-form remote opener.** The command takes no URL: it always opens `https://innocentpenguin.com/` (constant, optionally a path on that host from an allow-list like `/customs`, `/leaderboards`, `/rl-tournament`). `build_url` keeps refusing everything else, so the "local pages only" safety stays intact. `on_navigation` allows only `innocentpenguin.com`, the Twitch/Google OAuth hosts the site's sign-in uses (`id.twitch.tv`, `www.twitch.tv` for the consent page only) and returns false for anything else; blocked links open in the user's default browser. `on_new_window` does the same.
3. **Own icon.** New `App/src-tauri/icons/site.ico` / `site.png` (penguin face on an orange/dark rounded tile with a small globe-or-"www" corner mark so it reads as "the website", distinct from the Suite ring logo and from the site favicon). Set with `.icon()` at build time (title bar and taskbar button). Generated by a new script `App/tools/make_site_icon.py` next to `make_icons.py`.
4. **Own taskbar entry and title.** Window title `Innocent Penguin - Website`. Different icon plus its own window title gives a visibly separate button, but Windows groups by process AppUserModelID, so by itself it would be stacked under the Suite button. To get a truly separate entry I propose setting a per-window AUMID (`gg.pinguino.suite.site`) with `SHGetPropertyStoreForWindow` + `PKEY_AppUserModel_ID` (small `windows`-crate block, Windows only, ~25 lines, in a new `siteicon.rs`). Risk: a per-window AUMID needs a matching relaunch shortcut to pin properly; unpinned running entry works. **Fallback if that proves flaky: icon + title only (still its own button label and icon, may group).** Needs a real Windows check once built.
5. **Login persistence.** Give the site window its own WebView2 profile: `.data_directory(<app data>/webview-site)`. Cookies and localStorage then persist across launches in that folder (the browser engine encrypts cookies itself), isolated from the Suite UI profile so the site never shares storage with the shell. We never read, log, or copy cookies/tokens, and no credentials are written to any file or chat. The user signs in once through the site's normal Twitch button inside the window. A "Sign out / clear site data" item deletes that one folder (window must be closed first). Note: a WebView2 profile folder must be created before the first window opens and cannot be shared with another environment that uses different options; keeping it separate avoids that.
6. **Tray / window behaviour.** Tray unchanged. Pop-outs "really close" today; the site window follows the same rule. Nothing about the main window changes.
7. **Site-side (05) needs, small:** (a) no outbound-to-Twitch links in the site UI. Done: the only one (home sub note) was removed in e6af8b6, pushed. (b) The site detects the app window via a `?app=1` query or user-agent suffix added by `.user_agent()` to hide the "Open in app" prompt if one is ever added. Optional, not needed for v1. (c) Sign-in redirects must stay on `innocentpenguin.com` -> `id.twitch.tv` -> back, which `on_navigation` allows.
